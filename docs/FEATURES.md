## 2. 运营后台

地址：`http://localhost:18081`（默认端口）。账号 `admin / admin123`。

### 2.1 数据看板

首页即看板，数据实时汇总自 PostgreSQL。

**KPI 区（五张卡片）**

| 指标 | 口径 |
| --- | --- |
| 今日成交额 | 今日 `已完成/待发货/待收货` 订单的实付金额合计 |
| 近 7 天成交额 | 同上，滚动 7 天，附环比 |
| 近 7 天订单 | 滚动 7 天订单数，附环比 |
| 客单价 | 近 30 天实付金额 ÷ 订单数 |
| 会员总数 | 全部未删除会员，附近 7 天新增 |

**图表**

- 成交趋势：面积图（成交额）叠虚线（新增会员），可切近 7 / 14 天。悬停显示当日数值。
- 品类销量分布：横向条形，按一级分类聚合。

**榜单**

- 热销商品 TOP 6：按销量降序，前三名序号高亮。
- 高价值会员：按累计消费降序。

顶部还有三个待办角标：待发货、待付款、退款中，直接反映需要处理的量。

### 2.2 商品管理

**商品列表**（`/products`）

- 搜索：按商品名称模糊匹配
- 筛选：分类、上下架状态
- 列表列：商品（图 + 名称 + ID + 分类品牌 + 新品/热销/推荐标签）、价格（含划线原价）、库存（低于 20 标红）、销量、浏览量、状态开关、操作
- 状态开关即时生效，无需进详情

**商品编辑**（`/products/new`、`/products/:id/edit`）

- 基础信息：名称、副标题、分类、品牌、封面、图集、详情富文本
- 价格：售价、原价、单位
- 规格矩阵：定义若干维度（如"尺码"、"颜色"）及取值，系统按前两个维度笛卡尔积生成 SKU 行，逐行设价格与库存
- 标记：新品 / 热销 / 推荐
- 排序权重

> **SKU 生成规则**：仅取前两个规格维度组合，最多 9 个 SKU。无规格的商品自动生成一个"标准" SKU。

### 2.3 分类与品牌

**分类**（`/categories`）——两级树，前台分类页与筛选面板共用。删除前会校验：有子分类或有商品时拒绝。

**品牌**（`/brands`）——用于商品归属与前台筛选，含 Logo 与简介。

### 2.4 订单管理

**列表**（`/orders`）

- 状态标签页：全部 / 待付款 / 待发货 / 待收货 / 已完成 / 已取消 / 退款
- 搜索：订单号、收货人、手机号
- 筛选：来源（H5/网页、小程序）、下单日期区间
- 列：订单号（含时间）、首件商品（图 + 名称 + 规格 × 数量 + "等 N 件"）、买家（昵称 + 平台）、金额、状态、操作

**详情抽屉**

- 订单信息、收货信息、支付方式、物流单号、买家留言
- 商品明细（逐行图、名、规格、单价、小计）
- 金额明细（商品金额、运费、优惠、实付）
- 商家备注（仅内部可见，独立于买家留言）

**操作**

| 操作 | 前置状态 | 效果 |
| --- | --- | --- |
| 发货 | 待发货 | 填快递公司 + 单号 → 待收货，买家可见物流 |
| 退款 | 待发货 / 待收货 / 已完成 | 归还库存；余额支付退回余额，第三方渠道走原路退款 → 已退款 |
| 备注 | 任意 | 写入内部备注，不影响买家 |

所有操作都会写进操作日志。

### 2.5 会员管理

**列表**（`/members`）——支持按昵称/手机号搜索，按注册来源、启用状态筛选。

列：会员（头像 + 昵称 + 手机号脱敏）、等级、累计消费、订单数、积分/余额、来源、最近登录、启用开关。

**详情抽屉**——会员 ID、性别、来源、累计消费、订单数、积分、余额、注册时间、最近登录。

> **等级是展示字段。** 新会员注册时固定为 1 级，`total_spent` 与 `order_count` 会随订单累加，但没有触发升级的逻辑；种子数据里级别较高的会员是直接写入的。若要实现按消费额升级，需在结算累加消费后补一段判定。

### 2.6 优惠券

（`/coupons`）建券模板，两种类型：

- **满减券**：满 X 减 Y
- **折扣券**：满 X 打 N 折（如 8.5 折 = 应付 85%）

可设发行总量、每人限领、领取后有效天数。列表显示领取进度（已领 / 总量）。

券在 C 端"领券中心"领取，结算页可选用，也可不选（系统会自动挑最优）。

### 2.7 支付渠道

（`/pay-channels`）这是本系统比较特别的一块——渠道完全由运营配置，改完即时生效。

**列表** 显示四个渠道（微信支付、支付宝、Stripe、模拟支付）及其：模式（演示/沙箱/生产）、配置状态、已配置的凭据类型、启用开关、操作。

**配置弹窗**按所选渠道类型动态渲染字段：

| 渠道 | 需要填写 |
| --- | --- |
| Stripe | Secret Key（`sk_` 开头）+ Webhook 签名密钥 |
| 微信支付 | AppID、商户号、商户私钥、APIv3 密钥、商户证书序列号 |
| 支付宝 | 应用 AppID、应用私钥、支付宝公钥 |
| 模拟支付 | 无需任何凭据 |

**凭据处理规则：**

- 加密后落库（AES-GCM），页面只显示"是否已配置"
- 修改时留空即保持原值，不会被清空
- 配置不完整的渠道，启用开关是禁用的——避免结账时才发现不可用

**检测** 按钮校验必填项是否齐全，返回具体缺哪一项。

**启用** 后该渠道立即出现在 C 端结算页。

### 2.8 营销运营位

**轮播图**（`/banners`）——首页大图，可跳转商品 / 分类 / 外链，带排序与启停。

**公告**（`/notices`）——首页滚动条与列表，用于活动说明、物流提示。

### 2.9 操作日志

（`/logs`）由 `@OperationLog` 切面自动记录，含操作人、模块、动作、请求参数、耗时、时间。支持按操作人/动作/接口搜索。

### 2.10 存储与配置

（`/settings`）只读展示当前存储后端（本地磁盘 / S3）、访问前缀、单文件大小上限、允许的扩展名，以及数据库与 Redis 的基本信息。

**图片上传** 在商品、品牌、轮播编辑处使用，走 `/api/admin/files/upload`，按扩展名与大小校验。

## 3. PC 商城

地址：`http://localhost:18083`。账号 `13800138000 / 123456`。

### 3.1 首页

从上到下：

1. **全幅 hero 轮播**——四张主视觉，自动轮播（悬停暂停、可键盘操作），右侧有 01–04 进度轨。每张对应一个营销主题并带 CTA。
2. **服务承诺条**——包邮、退换、正品、免费装配四格。
3. **品类图墙**——六个一级分类，显示商品数。
4. **编辑推荐**——八个商品，按推荐标记与排序权重。
5. **本期主推**——双栏特稿，左图右文。
6. **新品上架**——六个最新商品。
7. **活动横幅**——全幅图叠文案与按钮。
8. **热销榜**——六个热销商品。
9. **加入会员**——注册引导。

### 3.2 商品列表

- 左侧筛选栏：分类树（两级，带商品数）、价格区间
- 顶部：结果数量、排序胶囊（最新 / 销量 / 价格升降）、移动端折叠为"筛选"按钮
- 商品卡：图、新品/热销标记、名称、价格（含划线原价）、已售数
- 分页为"加载更多"，显示剩余数量

搜索通过顶栏输入框进入，结果为关键词过滤。

### 3.3 商品详情

- 左：竖排缩略图 + 大图（可切换）
- 右：品牌行、商品名、副标题、价格、库存状态
- 规格选择：按维度渲染可选值，**无库存的组合自动置灰**
- 数量步进器（上限为当前 SKU 库存）
- 加购 / 立即购买（未选全规格时提示）
- 服务承诺三行
- 下方：商品详情正文、相关推荐

### 3.4 购物车

- 逐行：勾选框、图、名称、规格、单价、数量步进、小计、移除
- 全选、已选数量
- 库存不足或已下架的规格会内联提示
- 右侧摘要：已选件数、商品金额、运费（结算时计算）、合计
- 去结算 → 跳到结算页

### 3.5 结算下单

1. **收货地址**——列出地址簿，单选；可直接新增（弹窗）
2. **商品清单**——逐行展示，含规格与数量
3. **支付方式**——按运营启用的渠道动态渲染（见下）
4. **订单备注**——选填
5. **订单摘要**——优惠券选择（可不用）、金额明细、应付

提交后：

- 先创建订单
- 再按所选渠道发起支付，返回三种形态之一：
  - **跳转**（Stripe / 支付宝）——离开本站前往支付页
  - **二维码**（微信）——页面内展示二维码并轮询，支付成功后自动跳转
  - **页内完成**（模拟支付）——直接进订单详情

### 3.6 账户中心

| 页面 | 内容 |
| --- | --- |
| 账户概览 | 积分 / 余额 / 订单数 / 可用券、四个订单状态入口、最近订单 |
| 我的订单 | 状态标签页、订单卡（首件商品、实付、优惠额）、待付款可去支付/取消、待收货可确认 |
| 订单详情 | 状态横幅、商品明细、收货信息、订单信息、金额明细、按状态显示操作按钮 |
| 优惠券 | 我的券（可用/已用/已过期）、领券中心（可领取的模板） |
| 收货地址 | 列表、新增/编辑/删除、设为默认 |
| 个人资料 | 昵称、性别、头像地址，以及消费/订单/积分/余额统计 |

### 3.7 主题与语言

- **主题**：顶栏日/月图标切换浅色 / 深色，选择记入 `localStorage`。切换后页面外壳、遮罩、商品图（亮/暗两套）同步变化。
- **语言**：顶栏地球图标切换简体中文 / English / 日本語。界面文案与商品内容同时切换，选择记入 `localStorage`。默认跟随浏览器语言。

## 4. H5 / 小程序

地址：`http://localhost:18082`。移动优先，可直接被小程序 webview 加载。

功能与 PC 商城对应，布局为移动形态：

- **首页**：轮播、快捷入口、公告跑马灯、分类宫格、推荐/新品/热销分区
- **分类页**：左侧一级分类栏 + 右侧商品列表
- **商品列表**：搜索、排序、下拉加载
- **商品详情**：图集滑动、规格选择、SKU 匹配、库存约束
- **购物车**：勾选、改数量、删除、全选、合计
- **结算**：地址、优惠券（含"不使用优惠券"）、支付方式、备注
- **订单**：列表（按状态）、详情、支付、取消、确认收货
- **个人中心**：订单角标、优惠券、地址簿、资料编辑
- **登录**：密码 / 短信验证码 / 微信一键登录

小程序宿主若通过 `?token=` 传入，前端会吸收该 token 并带上 `X-Client-Platform: mp`，订单因此能区分来源。

## 5. 跨端能力

### 5.1 账号与数据互通

同一套后端，同一份账号、购物车、订单、地址、券。在 PC 加购，手机上能看到；在小程序下单，后台与 PC 都能查到。

### 5.2 支付

三端共用同一套支付渠道配置。运营在后台启用某个渠道后，三端同时出现该支付方式。

### 5.3 图片

商品图存在后端 `static/images/`，由三个站的 nginx 反向代理到后端，因此后台看到的图与前台一致。

## 6. 业务规则

集中列出容易被问到的规则：

| 规则 | 值 | 位置 |
| --- | --- | --- |
| 订单支付超时 | 45 分钟，超时自动取消并归还库存 | `OrderServiceImpl.PAY_TIMEOUT_MINUTES` |
| 自动确认收货 | 发货满 7 天 | `OrderServiceImpl.autoCompleteShipped` |
| 免运费门槛 | 商品金额满 ¥99 | `FREE_SHIPPING_THRESHOLD` |
| 未达门槛运费 | ¥8 | `FLAT_FREIGHT` |
| 会员等级 | 注册即 1 级（普通会员）；1–4 级对应普通/白银/黄金/钻石，仅作展示，**当前不会自动升级** | `MemberServiceImpl.levelName` |
| 券自动择优 | 结算预览时挑优惠最大的一张 | `CouponCalculator` |
| 券叠加 | 一单只能用一张 | `shop_order.coupon_id` |
| 库存扣减 | 下单即扣，取消/退款归还 | `ProductSkuMapper` |
| SKU 组合上限 | 前两个维度，最多 9 个 | 商品编辑页 |
| 商品库存预警 | 低于 20 显示红色 | 商品列表 |
| 后台角色 | `ROLE_ADMIN`、`ROLE_OPERATOR` 两个账号，**当前无权限差异**（代码中无角色校验） | `sys_admin.role` |
| 上传大小上限 | 10 MB / 单文件 | `StorageProperties` |

```bash
docker compose down -v && docker compose up -d
```

```bash
python3 scripts/smoke_test.py http://localhost:8080
```
